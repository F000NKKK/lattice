**Lattice** — это современная кроссплатформенная библиотека для Rust, предназначенная для настройки и анализа сетевой конфигурации операционной системы через единый строго типизированный API.

> **Статус:** На данный момент репозиторий содержит только базовую инфраструктуру (bootstrap). В нём нет ни реализации, ни крейтов, ни исходного кода. Разработка ещё не началась.

## Обзор

Операционные системы предоставляют доступ к сетевой конфигурации и состоянию через совершенно разные, низкоуровневые и зачастую платформо-специфичные интерфейсы: Linux Netlink, Windows IP Helper API, route sockets в BSD/macOS и различные проприетарные механизмы. Приложениям, которым необходимо анализировать или настраивать сеть — IP-адреса, маршруты, интерфейсы, соседей и многое другое, — как правило, приходится либо вызывать внешние утилиты через shell, либо парсить текстовый вывод, либо писать и поддерживать отдельные платформо-специфичные интеграции.

Lattice призвана объединить эти интерфейсы под единым, строго типизированным, идиоматичным API на Rust, чтобы потребителям никогда не приходилось иметь дело с сырыми платформенными структурами, shell-командами или произвольным парсингом строк.

## Мотивация

Кроссплатформенные сетевые инструменты в экосистеме Rust фрагментированы. Существующие решения зачастую платформо-специфичны, неполны или построены на вызове системных утилит, таких как `ip`, `netsh` или `route`. Это хрупко, сложно тестировать и не подходит для создания надёжного, production-grade программного обеспечения для управления сетью.

Lattice призвана закрыть этот пробел, предоставив единый, хорошо спроектированный уровень абстракции над нативными сетевыми API операционных систем.

## Философия

- **Строгая типизация вместо строк.** Потребители взаимодействуют с типизированными значениями Rust — адресами, префиксами, маршрутами, интерфейсами — а не с сырыми строками или shell-командами.
- **Нативные API, а не подпроцессы.** Lattice обращается напрямую к платформенным сетевым API (Netlink, IP Helper API, route sockets), а не вызывает внешние CLI-инструменты.
- **Кроссплатформенность по замыслу.** Единая поверхность API с платформо-специфичными реализациями, чтобы приложениям не приходилось делать особые случаи для каждой операционной системы.
- **Корректность и безопасность прежде всего.** Настройка сети — чувствительная область; библиотека должна затруднять представление некорректных состояний.
- **Постепенный, продуманный рост.** Функциональность добавляется осознанно, с вниманием к дизайну API и долгосрочной поддерживаемости, а не поспешно, чтобы покрыть все мыслимые сценарии использования.

## Долгосрочные цели

В перспективе Lattice планирует предоставить поддержку:

- IP-адресов
- Сетевых префиксов
- Маршрутов
- Интерфейсов
- Шлюзов
- Настройки DNS
- Таблиц соседей (ARP/NDP)
- VLAN
- VRF
- Сетевых пространств имён (namespaces)
- Интеграции с firewall
- Мониторинга сети и уведомлений об изменениях
- Транзакционной конфигурации
- Декларативной настройки сети

## Не входит в задачи проекта

- Lattice не является заменой полноценным демонам управления сетью (например, NetworkManager, systemd-networkd).
- Lattice не ставит целью предоставление интерфейса командной строки или графического интерфейса в составе основной библиотеки.
- Lattice не ставит целью парсинг или оборачивание вывода внешних CLI-инструментов в качестве долгосрочной стратегии.
- Lattice не ставит целью поддержку всех мыслимых сетевых протоколов или вендорских расширений с первого дня.

## Текущий статус

На данный момент репозиторий содержит **только базовую инфраструктуру (bootstrap)**:

- Cargo workspace без членов (members)
- Метаданные репозитория и файлы для сообщества
- Конфигурацию GitHub (шаблоны issue, шаблон pull request, Dependabot)

Крейтов, исходного кода, примеров, тестов или бенчмарков пока не существует. Дизайн API и архитектурные решения ещё не приняты. Это сделано намеренно: репозиторий инициализируется до начала проектирования и реализации.

## Дорожная карта

1. **Bootstrap** *(текущий этап)* — инфраструктура репозитория, лицензирование, файлы для сообщества и настройка инструментов.
2. **Проектирование** — определение структуры крейтов, базовых абстракций и стратегии абстрагирования платформ. См. [ARCHITECTURE.md](ARCHITECTURE.md) (на английском) для планируемой структуры workspace.
3. **Фундамент** — реализация базовых типов (адреса, префиксы, интерфейсы) и первого платформенного бэкенда.
4. **Паритет платформ** — расширение поддержки на Linux, Windows и BSD/macOS.
5. **Продвинутые возможности** — мониторинг, уведомления, транзакционная конфигурация и декларативная настройка сети.
